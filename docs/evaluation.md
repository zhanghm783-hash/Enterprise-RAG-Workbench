# 评测方法

## 资料与题集

TiDB语料来自[pingcap/docs-cn](https://github.com/pingcap/docs-cn)，固定commit为d99710dea88eac5f7437ec27acfa63aaa535b436。检索语料包含20篇文档、677个Chunk。

| 题集 | 用途 |
|---|---|
| enterprise_semantic_paraphrase_v1 | 24道语义问题，检索和忠实度方案对照 |
| enterprise_quality_faq_v1 | 24道短技术FAQ，回答表达优化对照 |
| 复杂文档样本 | 10份研报图像PDF＋10份表格DOCX，入库内容可用性对照 |

题集包含问题、参考答案、必要依据单元和等价Chunk映射。生成器接收用户问题与检索资料；评分阶段使用对应依据及标准。

## 1. Top5完整依据覆盖率

每题全部必要依据单元均被最终Top5覆盖时记1，否则记0；对24题计算成功比例。

| 方案 | 成功题数 | 覆盖率 |
|---|---:|---:|
| BM25 | 8/24 | 33.33% |
| 向量检索 | 11/24 | 45.83% |
| RRF融合 | 14/24 | 58.33% |
| 查询改写＋混合召回＋重排 | 22/24 | 91.67% |

改写使用qwen3.7-max，原问题加两条最多80字的技术问法；每路召回50个候选，经RRF融合后最多取100个候选送qwen3-rerank，最终返回5块。

结果：evaluation/results/retrieval.json。

## 2. 回答忠实度

使用Ragas 0.4.4、中文评分提示和qwen3.7-max裁判，按回答中受上下文支持的事实陈述比例评分，再对24题取平均。

- 前版：向量检索与qwen-plus自由回答。
- 后版：优化检索、完整候选正文、证据选择与原文摘录。
- 均值：0.35096 → 0.96528。
- 引用核对：38处。
- 拒答按0计的均值：0.92361。

结果：evaluation/results/faithfulness.json。

## 3. FAQ回答相关性

同24短FAQ、相同Top5来源和qwen3.7-max生成器，对照两版回答表达。后版保留真实章节标题，明确对象、触发条件及结论。

评分使用Ragas回答相关性、中文提示、qwen3.7-max裁判、text-embedding-v4、strictness=3，通过回答反推问题与原问题的语义相似度计算。

- 表达版本对照：0.85273 → 0.91756。
- 原向量自由回答参照：0.90555。
- 检索向量配置：text-embedding-v1，1536维。

结果：evaluation/results/relevancy.json。

## 4. 复杂文档可用入库率

同20份文档，对照原生解析与OCR增强：PDF图像输入视觉OCR，DOCX使用原生解析，统一经过切分、向量化、PostgreSQL和Milvus写入。

可用判据：

- 正文4字符锚点覆盖≥90%。
- 表格有效单元内容覆盖≥95%。
- 行内关联≥90%。
- 至少产生1个Chunk，存储内容满足相同判据，两库记录对应。

| 判定方式 | 原生解析 | OCR增强 |
|---|---:|---:|
| 内容显示等价 | 10/20，50% | 19/20，95% |
| 逐字匹配 | 10/20，50% | 16/20，80% |

显示等价审计在首轮识别后增加，对前后两侧统一重算，统一大小写、标点、数学符号和同行单元格的显示形式；数字、单位及行内对应关系继续参与检查。

结果：evaluation/results/ingestion.json。

## 结果复算

```sh
python evaluation/verify_summary.py
```

脚本读取公开逐题与逐文件记录，复算计数和均值。

## 运行评测脚本

1. 按evaluation/corpus_sources中的固定版本准备语料。
2. 完成本地入库，建立实际Chunk ID与必要依据的映射。
3. 保存数据快照与版本哈希。
4. 运行evaluation/scripts中的入库、检索、回答生成及评分脚本。
5. 汇总逐题结果，保存各版本对照记录。

模型调用通过本地.env配置；付费脚本使用--allow-paid参数。评测链路的查询改写、重排、抽取式回答和视觉OCR分别位于evaluation/scripts；网页与API链路位于backend/app。
